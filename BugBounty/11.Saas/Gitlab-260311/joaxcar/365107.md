## Original Report

####  Summary

An owner/maintainer of a (premium +) top group can configure SAML SSO requirements for access to the group. See documentation [link](https://docs.gitlab.com/ee/user/group/saml_sso/). If the group activate the setting "Enforce SSO-only authentication for web activity for this group" no user that does not have an active SSO session with the configured provider is restricted from accessing the group (and private projects in the group)

In the docs for "SSO enforcement" [link](https://docs.gitlab.com/ee/user/group/saml_sso/index.html#sso-enforcement) this is stated

> Credentials that are not tied to regular users (for example, project and group access tokens, and deploy keys) do not have the SSO check enforced. 

As far as I can read in the docs `Trigger tokens` [link](https://docs.gitlab.com/ee/ci/triggers/#create-a-trigger-token) should not fall in this category as they are tied to the user that creates the token. And any jobs are run as the user that created the token.

As it turns out, trigger tokens are not blocked by SSO enforcement. And the user can thus trigger tokens with arbitrary variables without having an active SSO session.

####  Steps to reproduce

1. Create a user `user01`  
2. Create a group with at least `Premium` subscription (create an ultimate trail if needed), lets call it `group01`  
3. Create a `private` project in the group, lets call it `project01`  
4. In the project create the file  
 .gitlab-ci.yml  
```yml  
build-job:  
  stage: build  
  script:  
    - echo "just doing something"  
```  
5. Go to https://gitlab.com/joaxcarultimate3/test3/-/settings/ci_cd and expand `Pipeline triggers`  
6. Create a pipeline trigger token, take a note of it  
7. Now go to group settings https://gitlab.com/groups/group01/-/saml and configure a SAML provider (you can fake the provider, use any URL and use a valid fingerprint. use mine `D0:E8:0F:EA:ED:40:9E:7E:D2:54:4E:25:39:7C:4F:1B:12:A5:EF:DF` if you dont have one.)  
8. Check the boxes  
  * Enable SAML authentication for this group  
  * Enforce SSO-only authentication for web activity for this group  
9. Click save.  
10. Try to go to https://gitlab.com/joaxcarultimate3/test3/-/pipelines this will ask you to SSO authenticate  
11. Now send this request in a terminal (replace TOKEN and PROJECTID  
```bash  
curl -X POST \  
     --fail \  
     -F token=TOKEN \  
     -F ref=main \  
     https://gitlab.com/api/v4/projects/PROJECTID/trigger/pipeline  
```  
12. You will get a response that a pipeline have run  
13. If you now uncheck the SSO requirement and go to https://gitlab.com/joaxcarultimate3/test3/-/pipelines you will see that it has run

####  Impact

Pipeline trigger tokens can be used to trigger pipelines with arbitrary variables by a user that should not have access to the project due to missing SSO session

####  What is the current *bug* behavior?

Trigger tokens work without SSO session if it is enforced

####  What is the expected *correct* behavior?

Trigger tokens should not work without SSO session if it is enforced
