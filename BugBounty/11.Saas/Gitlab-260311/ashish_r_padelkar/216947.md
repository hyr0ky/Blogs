### Summary

Hello,

When issue is moved from one private project to another, the related branches of the issue are visible to the reporters (and higher) which actually belongs to the private project

### Steps to reproduce

1. Create a new issue in private projectA.  
2. Add 2-3 branches to this issue using `Create merge request` option from an issue. Only create branches not merge requests.  
3. Now move this issue in some other projectB.  
4. Login as Reporter in the projectB (but no access to projectA) and see the issue. You should see the branches created on this issue through system notes. This actually belongs to old private project where it was moved from.



### What is the current *bug* behavior?

Related branches of the issue are visible to reporters of new project where the issue is moved to.

### What is the expected *correct* behavior?

System notes which reveals branches from a source project should be removed when issue is moved


### Output of checks

This bug happens on GitLab.com

Ashish

## Impact

System notes reveals related branches of issue which is moved from private project for the reporters
