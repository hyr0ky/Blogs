## Report

#####  Summary

Hello,

When project owner imports the issues from Jira, One of the following Graphql is executed.

```  
[{&#34;operationName&#34;:null,&#34;variables&#34;:{&#34;fullPath&#34;:&#34;groupnew321/project_1&#34;},&#34;query&#34;:&#34;query ($fullPath: ID!) {\n  project(fullPath: $fullPath) {\n    jiraImportStatus\n    jiraImports {\n      nodes {\n        ...JiraImport\n        __typename\n      }\n      __typename\n    }\n    services(active: true, type: JIRA_SERVICE) {\n      nodes {\n        ... on JiraService {\n          projects {\n            nodes {\n              key\n              name\n              __typename\n            }\n            __typename\n          }\n          __typename\n        }\n        __typename\n      }\n      __typename\n    }\n    __typename\n  }\n}\n\nfragment JiraImport on JiraImport {\n  jiraProjectKey\n  scheduledAt\n  scheduledBy {\n    name\n    __typename\n  }\n  __typename\n}\n&#34;}]  
```

In response, you can see the import status, jiraProjectKey etc. These info should not be visible to users without project membership( Should be visible only to Project Maintainer/owners) and particularly when issues are set as Team Members only. However, anyone can run the above Graphql request and obtain these information even when they are not a member of the project and issues are set as Team member only.

#####  Steps to reproduce

1. Create a public project and set issues as Team Members only so that only team members can see the issue.  
2. As an owner of the project, connect/integrate the  project with Jira at `/-/services/jira/edit`  
3. Once you integrate, you can now import the Jira issues at `/-/issues`  
![Screenshot_2020-11-06_at_00.18.23.png](https://h1.sec.gitlab.net/a/611c554f-1861-42ca-adfa-9a9c25f623fc/Screenshot_2020-11-06_at_00.18.23.png)

4. Import the issues 2-3 times.  
5. Login as another user who doesnt have membership in above project.  
6. Just run the below GraphQL query

```  
[{&#34;operationName&#34;:null,&#34;variables&#34;:{&#34;fullPath&#34;:&#34;groupnew321/project_1&#34;},&#34;query&#34;:&#34;query ($fullPath: ID!) {\n  project(fullPath: $fullPath) {\n    jiraImportStatus\n    jiraImports {\n      nodes {\n        ...JiraImport\n        __typename\n      }\n      __typename\n    }\n    services(active: true, type: JIRA_SERVICE) {\n      nodes {\n        ... on JiraService {\n          projects {\n            nodes {\n              key\n              name\n              __typename\n            }\n            __typename\n          }\n          __typename\n        }\n        __typename\n      }\n      __typename\n    }\n    __typename\n  }\n}\n\nfragment JiraImport on JiraImport {\n  jiraProjectKey\n  scheduledAt\n  scheduledBy {\n    name\n    __typename\n  }\n  __typename\n}\n&#34;}]  
```

7. You should see the Jira Import status, jiraProjectKey, how and at what time the import was done .


#####  Examples

You can run above query to reproduce the issue as it is from my test project from gitlab.com. It should show you some information about jira import although you can not see the issues from that project when you browse.

#####  What is the current *bug* behavior?

JIra import information visible to non members from public projects despite no access to issues

#####  What is the expected *correct* behavior?

These info should not be visible to anyone except Maintainers/owners of the project. Currently it shows without permissions to any users on gitlab.
