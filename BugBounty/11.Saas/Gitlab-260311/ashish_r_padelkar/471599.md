## Report

#####  Summary

Hello,

I reported similar issue earlier #2456229 and it was closed as informative as internal team was aware of it and already working on the fix. I see the fix has been merged here as per this comment `https://gitlab.com/gitlab-org/gitlab/-/issues/455813#note_1859326448` .

The fix obfuscate the email addresses also added via quick action on the issue `/add_email <email ID>` for unauthenticated users and works as intended. However, if the email address that ends their local part  with any of the allowed special characters, the email is still publicly visible.

For eg as per `https://en.wikipedia.org/wiki/Email_address#Local-part`, the local part of an email can contain `!#$%&'*+-/=?^_`{|}~` special characters. So if we anyone add emails that ends the local part with these characters, email is directly visible.

For eg `/add_email email#[@]example`. This will create system note on issue and is visible on issue timeline for any unauthenticated users.

#####  Steps to reproduce

1.Create an issue in your public project.  
2.Add an email  using quick action inside issue comment `/add_email email[@]example` .  
3.Now visit the issue link without authentication and you should see `email[@]example` is obscured.  
4.Now add `/add_email email#[@]example` .  
5.Now visit again , this time you should see email is publicly visible without authentication on issue timeline system note.

So any email that ends their local part with allowed special characters `!#$%&'*+-/=?^_`{|}~` will be publicly visible.


#####  What is the current *bug* behavior?  
External emails are publicly visible under certain conditions on issue system notes

#####  What is the expected *correct* behavior?

Email should be properly obscured when  email local part ends with allowed special characters.



#####  Output of checks

 This bug happens on GitLab.com

Regards,  
Ashish

####  Impact

External emails not obscured under certain conditions on issue system notes
