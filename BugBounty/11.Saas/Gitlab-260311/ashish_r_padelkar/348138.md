## Report

#####  Summary

Hello,

I reported similar issue before #635502 and it was resolved.

Not sure if there are any changes afterwards but this issue is appearing again for me. The list of packages are visible (and also downloadable now) to any unauthenticated users even when public project has repositories restricted only to team members. 

#####  Steps to reproduce

1. Create a public group and public project underneath.  
2. Go to project settings and set `Repositories` to be limited only to team members.

![Screen_Shot_2021-12-08_at_2.01.10_PM.png](https://h1.sec.gitlab.net/a/c86c4464-78fa-4065-ae42-f20085d07a33/Screen_Shot_2021-12-08_at_2.01.10_PM.png)

3. Since `Packages` are part of repositories, they shouldn't be visible to users without access to group or project.  
4. Now browse the url unauthenticated `https://gitlab.com/<GroupName>/<ProjectName>/-/packages` and you will see the packages as well as you can download the files (which was not possible during #635502).  
5. The permissions are correctly enforced at group level though. You CAN NOT see packages at group level `https://gitlab.com/groups/<GroupName>/-/packages`.



#####  Examples

You can browse my url unauthenticated `https://gitlab.com/g3220/githubimport/-/packages` and you will see list of packages and download the files inside it. 

Repositories for that projects are restricted only to team members.

Permissions correctly enforced at group level `https://gitlab.com/groups/g3220/-/packages`

#####  What is the current *bug* behavior?

Unauthenticated user can see and download packages of public projects whose repositories are restricted .

#####  What is the expected *correct* behavior?

When repositories are restricted, users without access to project shouldn't see packages l.



#####  Output of checks

This bug happens on GitLab.com

Regards,  
Ashish

####  Impact

Unauthenticated users can see and download packages from public projects whose repositories are restricted
