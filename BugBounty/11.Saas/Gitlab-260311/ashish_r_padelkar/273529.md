## Report

#####  Summary

Hello,

Email address of users are leaked even if they have set below settings in their profiles at `https://gitlab.com/-/profile` if they triggered the pipelines in public projects.

![Screenshot_2020-10-29_at_01.13.07.png](https://h1.sec.gitlab.net/a/6e0b57b0-328a-4d23-a431-8401a4607f3f/Screenshot_2020-10-29_at_01.13.07.png)

This happens in graphql request for `getPipelineHeaderData` when trying to see pipeline details and the email of user who triggered the pipeline is visible in response. 

As pipelines are publicly visible to all in public projects, emails of all the users who triggered the pipelines in such projects are visible publicly.

#####  Steps to reproduce

1. Go to any public project and go to any pipeline details page.  
2. Following request is sent in background.

```  
POST /api/graphql HTTP/1.1  
Host: gitlab.com  
Connection: close  
Content-Length: 748  
accept: */*  
X-CSRF-Token: 1  
User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_5) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/86.0.4240.111 Safari/537.36  
content-type: application/json  
Origin: https://gitlab.com  
Sec-Fetch-Site: same-origin  
Sec-Fetch-Mode: cors  
Sec-Fetch-Dest: empty  
Referer: https://gitlab.com/groupnew321/project2/-/pipelines/206490527  
Accept-Encoding: gzip, deflate  
Accept-Language: en-GB,en;q=0.9  
Cookie: 1

[{&#34;operationName&#34;:&#34;getPipelineHeaderData&#34;,&#34;variables&#34;:{&#34;fullPath&#34;:&#34;groupnew321/project2&#34;,&#34;iid&#34;:&#34;17&#34;},&#34;query&#34;:&#34;query getPipelineHeaderData($fullPath: ID!, $iid: ID!) {\n  project(fullPath: $fullPath) {\n    pipeline(iid: $iid) {\n      id\n      status\n      retryable\n      cancelable\n      userPermissions {\n        destroyPipeline\n        __typename\n      }\n      detailedStatus {\n        detailsPath\n        icon\n        group\n        text\n        __typename\n      }\n      createdAt\n      user {\n        name\n        webPath\n        email\n        avatarUrl\n        status {\n          message\n          emoji\n          __typename\n        }\n        __typename\n      }\n      __typename\n    }\n    __typename\n  }\n}\n&#34;}]  
```



3. The response contains `user` object which discloses the email address of the user even when public viewing is not allowed!


#####  What is the current *bug* behavior?  
Emails are visible of all users in public projects whoever triggered the pipeline .

#####  What is the expected *correct* behavior?

Email address shouldnt be visible publicly when users are not allowing it.



#####  Output of checks

This bug happens on GitLab.com

Regards,  
Ashish

####  Impact

Emails of users are visible publicly in pipeline detail graphql endpoint whoever triggered the pipelines.
