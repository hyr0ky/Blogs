### Summary
  
Hello,

When issue is moved from private project to public project, the following information from private project/group is visible in issue timeline

1. Private project/group milestone  
2. Private project label ID  
3. and because of above 2, Private project path from both were applied

### Steps to reproduce

1. Create a private group  
2. Create private project under it  
3. Create a issue in the project  
4. After creating the issue, apply milestone, label and epic to this issue. Each action should create timeline activities in issue.  
5. Now move this issue in public project.  
6. Login as non member and visit this public issue now and you should see timeline activity disclosing milestone name, label ID and Private group/project path from which it was moved.

![Screenshot_2019-10-01_at_15.42.59.png](https://h1.sec.gitlab.net/a/59e26a86-d70d-4589-aea7-f3785f3ed032/Screenshot_2019-10-01_at_15.42.59.png)




### What is the current *bug* behavior?

Discloses private group/project path, milestone name, label ID if issue is moved from private to public project

### What is the expected *correct* behavior?

This information should be hidden from non members



### Output of checks  
This bug happens on GitLab.com and might be on omnibus installations too!

Regards,  
Ashish

## Impact

Milestone name, label ID and private project path visible to non members when issue is moved from private to public project
