## Report

#####  Summary

Hello,

Looks like there is a design flaw which allows Reporters to change alerts status which are not visible to reporters. 

By design, alerts are only accessible to users with at-least `Developers` role . `https://docs.gitlab.com/ee/operations/incident_management/alerts.html#alert-list`

But the incidents created from this alerts are visible to all users.  Problem with this is , when these incidents are closed, the alert status gets changed to `Resolved` too! -  `https://docs.gitlab.com/ee/operations/incident_management/alerts.html#create-an-incident-from-an-alert`.

As  `Reporter` users are allowed to close incidents, they are indirectly changing the alert status to `Resolved` which shouldn't happen as per permission model as reporter users cant even see the alerts!.

Note that, developers or higher user can manually change the status of alerts through alert page but using above flaw, even reporters users can change the alert status which should not happen!

#####  Steps to reproduce

1. As a project admin, go to `https://gitlab.com/<NameSpace>/<ProjectName>/-/alert_management` and look for alert.

2. Go to its detail page and create an incident for this alert.

3. Now login as Reporter user in this project and try to browse `https://gitlab.com/<NameSpace>/<ProjectName>/-/alert_management` but you wont see this page as you dont have permission to view alerts.

4. Now go to issues at `https://gitlab.com/<NameSpace>/<ProjectName>/-/issues` and look for issues with `Incident` labels. 

5. As a reporter user, you are allowed to close the incident. Close the incident( to identify incident associated with alert, In incident description page you will see the alert link ).

6. Login as project admin again and browse to `https://gitlab.com/<NameSpace>/<ProjectName>/-/alert_management`.

7. You will see alert is moved in `Resolved` tab.


#####  What is the current *bug* behavior?

Reporters are allowed to change the alert status using the design flaw mentioned above!

#####  What is the expected *correct* behavior?

As per documentation, only users with at-least developer roles should be allowed to change the status.
