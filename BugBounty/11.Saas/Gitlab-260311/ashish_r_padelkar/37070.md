### Summary  
Hello,

This is similar to #744352 but with different settings and in this case milestones associated with releases are visible to unauthorised users and not vice versa.

When issues & Merge requests are set as only project members, milestone names shouldn't be visible to unauthorised users.

![Screenshot_2019-11-22_at_19.44.08.png](https://h1.sec.gitlab.net/a/8912813e-3ced-4755-b66f-e6d5457f25c3/Screenshot_2019-11-22_at_19.44.08.png)

but release page discloses the milestone name 


### Steps to reproduce


1. Create a public project with above settings.  
2. create a release with milestone using API  
3. Now login as non member and visit the release page and you should see the milestone name associated with release.



### What is the current *bug* behavior?

Milestone name associated with releases are visible

### What is the expected *correct* behavior?

Milestone names shouldnt be visible to unauthorised user



### Output of checks

This bug happens on GitLab.com and might be on omnibus installations too!

Regards,  
Ashish

## Impact

Milestone names visible in release page to unauthorised user
