## Report

#####  Summary

Hello,

As per new permissions, guest users are not allowed to create incidents. `https://docs.gitlab.com/ee/operations/incident_management/incidents.html#create-incidents-manually`.

This works fine , however guest users are still able to upload/delete metrics images to the incidents that they created by themselves( when they were reporters).

#####  Steps to reproduce

1. As a reporter user, create an incident in any of your project at `https://gitlab.com/<NameSpace>/<ProjectName>/-/issues/new?issuable_template=incident&issue%5Bissue_type%5D=incident`

2. Project Admin demotes the reporter user to guest user.

3. As a guest user, you can access the incident created in step1.

4. Click on metrics tab and you are still able to upload or delete any existing metrics uploaded there.

5. This is possible because incident was created by same user when they were reporter but this should not happen now as they have guest permissions.


#####  What is the current *bug* behavior?

Guest can upload and delete metrics images to incidents that they created when they were reporter. This should be restricted to users with reporter role only no matter who created the incidents.

#####  What is the expected *correct* behavior?

As mentioned above , only users with reporter roles should be allowed to upload/delete instead of whoever created the incident. 

#####  Output of checks

This bug happens on GitLab.com
