## Report

####  Summary  
According to the [documentation](https://docs.gitlab.com/ee/user/profile/index.html#private-profile) when a user sets his profile as private, other users won't be able to see the profile information which includes snippets too.  
But these snippets can accessed using Graphql for a specific user even If the user has set his profile to private using the grpahql [explorer] (https://gitlab.com/-/graphql-explorer)

####  Steps to reproduce  
1. Create snippets from a victim's account & set the profile as private from settings.  
2. Now open an incognito tab & go to the graphql [explorer] (https://gitlab.com/-/graphql-explorer)  
3. Paste the following query & hit enter.

```  
query {  
user(username:"<victim_username>"){  
snippets {  
  edges {  
    node {  
      id  
    }  
  }  
}
}  
}
```  
Now you can see all the snippets of the user & can access them with their id  using ```https://gitlab.com/-/snippets/<snippet_id>```

####  POC  
Let's use my account for a quick POC  
1. Go to [my account](https://gitlab.com/adarshshetty18) ,  you will see that I have a private profile with no snippets tab.  
2. Now go to the graphql [explorer] (https://gitlab.com/-/graphql-explorer)  
3. Paste the following query & hit enter.

```  
query {  
user(username:"adarshshetty18"){  
snippets {  
  edges {  
    node {  
      id  
    }  
  }  
}
}  
}
```  
You will be able to list all my snippets even If my profile is private  
![Screenshot_(20).png](https://h1.sec.gitlab.net/a/7f70398f-8713-4893-8c6c-8c593001334b/Screenshot_(20).png)

####  Impact

Even If the public snippets are available for access to everyone, the ability to list snippets of a particular user breaks the protection set by the user to make his profile information private. It leads to exposure of the snippets of a specific user.
