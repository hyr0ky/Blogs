## Report

**1. Description:**  
I found a scenario where unauthorized actor can read wiki pages where it is forbidden by issue description "Compare with previous version" feature - **[screenshot1.png]**

![screenshot1.png](https://h1.sec.gitlab.net/a/854ec6fd-56d4-4545-97d2-08888de4cdaa/screenshot1.png)

**2. Scenario:**

`I use Gitlab Ultimate Trial in Gitlab Cloud`

**2.1. Actors:**  
User A - owner of the public group A and owner of the public project A_PROJ (project inside group A)  
User B - for example just Internet user - even not registered Gitlab user

**2.2. Steps:**  
1. User A - in public project A_PROJ go to: `Plan` -> `Wiki` and create the Wiki Page  
2. User A - in public project A_PROJ go to: `Plan` -> `Issues` and create the public issue with title and description (e.g.: `title:` `test`, `description:` `test`)  
3. User A - in public project A_PROJ go to: `Settings` -> `General` -> `Visibility, project features, permissions` -> `Wiki` and set this option to `Only Project Members`  
4. User A - go to the PoC created issue and change the description of the issue - mention there the PoC created wiki page by `[[<wiki_page_title>]]`  
5. User B - go to the PoC public issue and notice that you see in the description of the issue `[REDACTED]` - expected behaviour - you don't have access to wiki pages of this project  
6. User B - in the PoC public issue click in the activity where User A changed the issue description `Compare with previous version` - notice that the system will show you the wiki page title without any problems - **[screenshot1.png]** - Reading Wiki pages where it is forbidden by issue description "Compare with previous version" feature

![screenshot1.png](https://h1.sec.gitlab.net/a/854ec6fd-56d4-4545-97d2-08888de4cdaa/screenshot1.png)

Best regards,  
Mateusz

####  Impact

- Reading Wiki pages where it is forbidden by issue description "Compare with previous version" feature
