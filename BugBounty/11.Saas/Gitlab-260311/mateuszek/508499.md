## Report

**1. Description:**  
In general I found a scenario where user with custom role "Read code" permission has unauthorized full access to the repository and its assets when owner disabled the Repository and all its assets (e.g.: in that case owner doesn't see the repository and all its assets - expected behaviour for every member). 


**2. Scenario:**

**2.1. Actors:**  
User A - victim - owner of the public project A and owner of the public project A_PROJ (project inside group A)  
User B - attacker - member of the public group A and public project A_PROJ with custom role: permissions `Read code`, `Base role: Guest`

**2.2. Steps:**  
1. User A - create a custom role in public group A:

`Settings` -> `Roles and permissions` -> `New`:  
`https://gitlab.com/groups/<group_A_name>/-/settings/roles_and_permissions`  
`Base role:` `Guest`  
`Custom permissions:` `Read code`  
2. User A - assign created custom role for User B:  
`https://gitlab.com/groups/<group_A_name>/-/group_members`  
3. User A - disable Repository and all its assets in the PoC public project A_PROJ:  
`Settings` -> `General` -> `Visibility, project features, permissions` -> `Repository` - turn off this feature then save changes  
4. User A - try to access to the Repository - you should see 404 Not Found - expected behaviour:  
`https://gitlab.com/<group_A_name>/<project_A_PROJ_name>/-/tree/main`  
5. User B - try to access to the Repository - notice that you have access to this module and all its assets without any problems :) - User with custom role "Read code" permission has full access to the repository even if owner disabled the Repository and all its assets
