## Report

**1. Description:**  
I found a weird behaviour of the Gitlab cloud system lets to "takeover" the public and private groups.  
For example if there exists a group created by User B with name: `mateuszek_poc_takeover`  
Then when User A will create a group named: `mateuszek_poc_takeover.html` THEN the Gitlab system will link the existing User B group with User A - User A will see the group created by User B in his groups AND when User A will enter to the created group (`mateuszek_poc_takeover.html`) then the system will redirect him to group of User B - BUT User A will not be a member of this group BUT User A can use the `Import groups by direct transfer` AND there will be visible for User A the group created by User B and User A can import it with its projects successfully! Maybe it is a bit complicated but something is there really not good :D

**2. Scenario:**

**2.1. Actors:**  
User A - attacker - Gitlab cloud user  
User B - victim - Gitlab cloud user

**2.2. Steps:**  
1. User B - create a public group in Gitlab cloud e.g.: named: `mateuszek_poc_blablabla_public`  
2. User B - create a private group in Gitlab cloud e.g.: named: `mateuszek_poc_blablabla_private`  
3. User B - add some group avatars to the created groups - for better understand the PoC  
4. User A - create a public group in Gitlab cloud named: `mateuszek_poc_blablabla_public.html`  
5. User A - create a private group in Gitlab cloud named: `mateuszek_poc_blablabla_private.html`  
6. User A - go to your profile -> `Groups` and notice that there are created groups by you in the previous steps BUT HERE WE ARE - try to enter for example to `mateuszek_poc_blablabla_public.html` AND notice that the system will redirect you to the group created by User B!!!! So at this point - we have in our created `Groups` the groups created by User B!!!  
7. User A - now, we will use the feature: `Import groups by direct transfer` - go to creating the new group feature then choose `Import group` THEN under: `Import groups by direct transfer`  
Type:  
`GitLab source instance base URL:` `https://gitlab.com`  
`Personal access token`: <USER A PAT TOKEN WITH api scope>  
Then click `Connect instance`

NOW, notice that in the next window: `Import groups by direct transfer` you can find the groups: `mateuszek_poc_blablabla_public.html` and `mateuszek_poc_blablabla_private.html` THAT ARE POINTING TO User B group, NOW notice that you can use Import feature of this groups without any problems and the system will return successful response!

I am still analyzing this weird behaviour of the Gitlab cloud system BUT something is really not good there.

Best regards,  
Mateusz

####  Impact

- Weird behaviour of the Gitlab cloud system lets to "takeover" the public and private groups
