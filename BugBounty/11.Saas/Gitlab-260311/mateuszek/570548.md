## Report

**1. Description:**  
I found a scenario where unauthorized user (group guest) can delete the parent epic of the epic by the command - Privileges escalation to delete parent epic by unauthorized users  
In general in relation to the Gitlab documentation related to epics:  
`https://docs.gitlab.com/ee/user/permissions.html#project-planning-group-permissions`  
Guests users **CAN"T** edit the epic - delete the parent epic of the epic - also in the UI there is no edit option in the area of parent epic of the epic - expected behaviour  
Guests can only view epics, add issue to an epic and add/remove child epics (**GUESTS CAN"T DELETE THE PARENT EPIC OF THE EPIC**)

**2. Scenario:**

**2.1. Actors:**  
User A - owner of the public group A  
User B - guest of the public group A

**2.2. Steps:**  
1. User A - create the public epic A in the group A  
2. User A - create the public epic B in the group A  
3. User A - set the parent epic for epic A as epic B  
4. User B - go to the PoC epic A and notice that you don't see the edit option in the area of the parent epic - expected behaviour - you can't delete the parent epic for the epic A  
5. User B - in the PoC epic A in the comment section use the below command:

`/remove_parent <URL_TO_THE_EPIC_B>`  
6. User B - notice that you deleted the parent epic (epic B) for the epic A without any problems - Privileges escalation to delete parent epic by unauthorized users
