## Report

#####  Summary

> I am not sure how to consider this report as a vulnerability in the template that needs to be fixed or as just a leak of secrets.

The build step of the `Terraform/Base.latest.gitlab-ci.yml`  template saves terraform artifacts `plan.cache` by default:

```yaml  
###  https://gitlab.com/gitlab-org/gitlab/-/blob/73524d97650ba59e29e97bc4e377a6587d780841/lib/gitlab/ci/templates/Terraform/Base.latest.gitlab-ci.yml#L46

.terraform:build:  
  stage: build  
  script:  
    - gitlab-terraform plan  
    - gitlab-terraform plan-json  
  resource_group: ${TF_STATE_NAME}  
  artifacts:  
    # The next line, which disables public access to pipeline artifacts, may not be available everywhere.  
    # See: https://docs.gitlab.com/ee/ci/yaml/#artifactspublic  
    public: false  
    paths:  
      - ${TF_ROOT}/plan.cache  
    reports:  
      terraform: ${TF_ROOT}/plan.json  
```

Despite the fact that `public: false` is set `plan.cache` will be uploaded to job artifacts because this feature does not work at the moment as can be seen at https://docs.gitlab.com/ee/ci/yaml/#artifactspublic As a result, extending this step may lead to secrets disclosure if builds are publicly available.

I found the https://gitlab.com/gitlab-org/ci-cd/deploy-stage/demos/gcp-oidc-test project that uses the vulnerable template at  https://gitlab.com/gitlab-org/ci-cd/deploy-stage/demos/gcp-oidc-test/-/blob/e22142995c91587e9c287d74399c99377d6e2344/.gitlab-ci.yml:

```yaml  
###  https://gitlab.com/gitlab-org/ci-cd/deploy-stage/demos/gcp-oidc-test/-/blob/e22142995c91587e9c287d74399c99377d6e2344/.gitlab-ci.yml#L11  
cluster:plan:  
  extends: .terraform:build  
  stage: plan-infra  
 # ...  
```

Due to this unexpected default behaviour a bunch of secrets, including PATs and GitLab Runner Token, leaked to the job artifacts. For example:

#####  What is the current *bug* behavior?

Terraform CI template uploads `plane.cache` to job artifacts by default and sensitive data may leak to job artifacts.

#####  What is the expected *correct* behavior?

Sensitive data are not leaked to job artifacts.
