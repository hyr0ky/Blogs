**[HackerOne report #765201](https://hackerone.com/reports/765201)** by `xanbanx` on 2019-12-27, assigned to @ankelly:

Hi GitLab security team,

### Summary

GitLab recently added the ability to export groups. Maintainers can perform this action and download the exported group in form of an archive. Furthermore,   
GitLab users can set their email to private thus these email addresses should not be leaked to other users. However, the new group export does not respect this setting. The private user email is leaked via the group export feature. Thus a malicious user can abuse this feature, add people to the group, and then get their private email address.

### Steps to reproduce

1. Create a new group  
2. Add some users, which set their email address to private, to the group  
3. Export the the group by calling: `curl -X POST --header "PRIVATE-TOKEN: Token" https://example.gitlab.com/api/v4/groups/<id>/export`  
4. Download the exported group via `curl --header "PRIVATE-TOKEN: Token" https://example.gitlab.com/api/v4/groups/<id>/export/download -o group.tar.gz`  
5. Extract the archive and inspect the containing `group.json`. Here you will find a members section like the one below, which leaks the private email address of all members.

```json  
...  
"members": [  
    {  
        "id": 1,  
        "access_level": 10,  
        "source_id": 2,  
        "source_type": "Namespace",  
        "user_id": 23,  
        "notification_level": 3,  
        "created_at": "2019-12-27 17:45:04 UTC",  
        "updated_at": "2019-12-27 17:45:04 UTC",  
        "created_by_id": 1,  
        "invite_email": null,  
        "invite_token": null,  
        "invite_accepted_at": null,  
        "requested_at": null,  
        "expires_at": null,  
        "ldap": false,  
        "override": false,  
        "user": {  
            "id": 23,  
            "email": "foo@bar.com",  
            "username": "foo"  
        }  
    },  
    ...  
]
```

### Impact

This vulnerability leaks the private email address of users. A malicious user can simply create a group and then add all users of a Gitlab instance, or even on gitlab.com, the group and then export it to get their private email address.

### What is the current *bug* behavior?

The group export leaks the private email address of any user.

### What is the expected *correct* behavior?

The group export feature should not leak the private email address of users.

### Output of checks

This bug happens on GitLab.com, running on GitLab Enterprise Edition 12.7.0-pre 7ed33754ed4
