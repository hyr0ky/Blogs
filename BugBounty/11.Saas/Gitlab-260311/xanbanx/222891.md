**[HackerOne report #900345](https://hackerone.com/reports/900345)** by `xanbanx` on 2020-06-17, assigned to @ngeorge1:

Hi GitLab Security Team,

### Summary

GitLab has a feature of external users, which have restricted access to the application. In general, these users only have access to resources they are explicitly granted to. Furthermore, they cannot create projects. The documentation at https://docs.gitlab.com/ee/user/permissions.html#external-users-core-only states this in here: `Cannot create groups, projects, or personal snippets.`

However, this is not applied properly. If an external users is added as a maintainer member to a group, the external user can create new groups within that group, thus violating the capabilities of an external user.

### Steps to reproduce

1. As an administrator, create an external users  
2. Create a new group and add the external user with `Maintainer` rights to the group  
3. As the external user, create a new group within the group he was added to.

### Impact

External users can create groups in group namespaces, although that is not allowed according to the docs. Thus, external users are violating their capabilities.

### What is the current *bug* behavior?

External users can create new groups within a group although not allowed.

### What is the expected *correct* behavior?

External users are not allowed to create new groups. 

### Output of checks

Tested on a local installation of GitLab Enterprise Edition 13.1.0-pre f0af9f078cd.
