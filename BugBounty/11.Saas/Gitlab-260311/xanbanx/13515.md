**[HackerOne report #669550](https://hackerone.com/reports/669550)** by `xanbanx` on 2019-08-08, assigned to `jmatos_bgtvf`:

### Summary

GitLab has a feature of external users, which have restricted access to the application. In general, these users only have access to resources they are explicitly granted to. Furthermore, they cannot create projects. The documentation at `https://docs.gitlab.com/ee/user/permissions.html#external-users-permissions` states this in here:

`They will, like usual users, receive a role in the project or group with all the abilities that are mentioned in the table above. They cannot however create groups or projects, and they have the same access as logged out users in all other cases.`

However, this is not applied properly. If an external users is added as a developer member to a group, the external user can create new projects within that group, thus violating the capabilities of an external user.

### Steps to reproduce

1. As an administrator, create an external users  
2. As a group maintainer, add the newly created users to one group with `Developer` privileges. Note that the group must have enabled the setting `Allowed to create projects: Developers + Maintainers`  
3. Login as the external users. Within the group you can create a new project, thus violating the capabilities for an external user

Note, the external user can also create projects using different approaches, e.g., via forking to the group namespace.

### Impact

External users can create projects in group namespaces, although that is not allowed according to the docs. Thus, external users are violating their capabilities.

### What is the current *bug* behavior?

External users can create projects in group namespaces, although that is not allowed according to the docs.

### What is the expected *correct* behavior?

External users should not be able to create projects.
