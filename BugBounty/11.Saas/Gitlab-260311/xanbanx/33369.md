Hi GitLab Security Team,

### Summary

For public projects, GitLab allows to restrict the visibility of merge requests to project members only. However, even this is done, merge request IDs for pipelines are publicly visible for users without merge request access. The same issue happens in private projects, where `Guest` users without MR access can also read the associated merge request ID.

### Steps to reproduce

1. Create a public project and restrict merge requests to project members only  
2. Push some code and a CI configuration. Note that the CI configuration requires pipelines for merge requests enabled via `only: merge_requests` like the following example:

```yaml  
image: busybox:latest

build1:  
  stage: build  
  script:  
    - echo "Do your build here"

test1:  
  stage: test  
  script:  
    - echo "Do a test here"  
    - echo "For example run a test suite"  
  only:  
  - merge_requests

test2:  
  stage: test  
  script:  
    - echo "Do another parallel test here"  
    - echo "For example run a lint test"  
```

3. Push some code and create a merge request  
4. As an unauthenticated user, `https://example.gitlab.com/<namespace>/<project>/pipelines/<pipeline-id>`, where <pipeline-id> is the ID of the pipeline associated with this merge request. The pipeline list shows them as `detached`  
5. This page leaks the associated merge request ID

The same happens for private projects, where guest user members of the project can also see the merge request ID on the same page.

### Impact

Merge request ID is visible to unauthorized users.

### Examples

As an unauthenticated user, visit https://gitlab.com/wter33/test-ci/pipelines/82944750. Here, the associated merge request `!1` is referenced.

### What is the current *bug* behavior?

Merge request ID leaked to unauthorized users despite merge requests are restricted to project members only or user only has guest access to the project (thus no merge request access).

### What is the expected *correct* behavior?

When merge requests are restricted to project members only or user is a guest member of the project, the pipelines view should not display the associated merge request ID.
