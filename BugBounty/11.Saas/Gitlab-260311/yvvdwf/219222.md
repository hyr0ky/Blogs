Dear team,

### Summary

XSS can occur in the labels' description. The exploitation is the same as in #831962. Consequently it occurs on Firefox. It does not work on Webkit-based ones such as Safari, Chrome. I haven't tested on Edge.  
It must occurred also in older browser due to [`svg4everybody()`](https://gitlab.com/gitlab-org/gitlab/-/blob/master/app/assets/javascripts/commons/polyfills/svg.js#L11) and [`cachedDocument.body.innerHTML = xhr.responseText`](https://github.com/jonathantneal/svg4everybody/blob/v2.1.9/dist/svg4everybody.js#L36)


### Steps to reproduce

1. Create a new label with any title but the following description: `description &amp;lt;svg&amp;gt;&amp;lt;use xlink:href="/yvvdwf/data/-/raw/js/xss.svg#xss"/&amp;gt;&amp;lt;/svg&amp;gt;`

2. Open an issue or create a new one, then assign the label above to it

3. In the Discussion of the issue, you should see a text confirming that the label has been added to the issue. Hover cursor over the label's title, an alert will be fired.

### Impact

Attacker may perform arbitrary actions on behalf of users at the client side.

### Examples

An example is on https://gitlab.com/yvvdwf/svg-use-xss-firefox  
This project is private. Please let me know if you cannot access it.

### What is the expected *correct* behavior?

Malicious scripts must not be executed due to svg content.
