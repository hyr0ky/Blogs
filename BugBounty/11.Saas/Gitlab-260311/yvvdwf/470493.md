## Report

Hi team,

This report is created as being required by Gitlab security team. It is to represent an issue to be separated with the one being reported in [2578672](https://hackerone.com/reports/2578672). Thus please refer to 2578672 for any further information.

Gitlab limits strictly scope of `CI_JOB_TOKEN` to prevent it from accessing to other projects [unless](https://gitlab.com/gitlab-org/gitlab/blob/e8337d749571f69a04a59bba49b3959acd7cb736/app/policies/project_policy.rb#L736-751) users explicitly configures their projects to allow it to access to.

```ruby  
  # If the project is private  
  rule { ~public_project & ~internal_access & ~project_allowed_for_job_token }.prevent_all

  # If this project is public or internal we want to prevent all aside from a few public policies  
  rule { public_or_internal & ~project_allowed_for_job_token }.policy do  
    prevent :guest_access  
    prevent :public_access  
    prevent :reporter_access  
    prevent :developer_access  
    prevent :maintainer_access  
    prevent :owner_access  
  end

  rule { public_project & ~project_allowed_for_job_token }.policy do  
    prevent :public_user_access  
  end  
```

Unfortunately, Gitlab does not explicitly prevents  from creating a new pipeline, thus [this policy](https://gitlab.com/gitlab-org/gitlab/blob/f1ffab963db9fb319650a7070b1d24f6601d3942/ee/app/policies/ee/project_policy.rb#L817-821) is still valid when this token is generated in a CI job which was triggered by a `gitlab-security-policy-bot`:

```ruby  
      rule { security_policy_bot }.policy do  
        enable :create_pipeline  
        enable :create_bot_pipeline  
        enable :build_download_code  
      end  
```

Furthermore, Gitlab [prevent multiple project membership for security policy bot users](https://gitlab.com/gitlab-org/gitlab/blob/6daf5aadc6dd73b2f7bbc76f2ee845b5af5122b2/ee/app/models/ee/project_member.rb#L20-24), , but it does not prevent this bot from being a member of a group. Thus attackers can add this bot as a group member via [bulk import](https://gitlab.com/gitlab-org/gitlab/blob/bc2f3979aefbe6d6e9b4f892813778e9a46e5bc0/lib/bulk_imports/common/pipelines/members_pipeline.rb#L33), then abuse this bot to bypass cross project access restriction as explained in [2578672](https://hackerone.com/reports/2578672).

###  Reproduce

Please refer to [2578672](https://hackerone.com/reports/2578672) for reproduction steps and a video demo

####  Impact

Attacker can abuse `gitlab-security-policy-bot` to bypass cross project access restriction and execute CI/CD pipeline on that project.
