### CodeQL Python 数据流分析核心摘要

#### 1. 核心概念与库

数据流分析用于追踪数据在程序中的传播路径。CodeQL for Python 提供了模块化的 API（自 2.13.0 版本起，旧库已弃用）。

|分析类型|描述|主要用途|性能与精度|
|---|---|---|---|
|**本地数据流 (Local Data Flow)**​|在单个函数/可调用对象内部追踪数据流。|分析函数内的值传播，适用于许多内部逻辑检查。|更快、更精确。|
|**本地污点跟踪 (Local Taint Tracking)**​|扩展本地数据流，包含**非值保留**的步骤（如字符串拼接 `y = “Hello ” + x`）。|追踪污染（如用户输入）在函数内的扩散。|比纯数据流更宽松，涵盖更多传播场景。|
|**全局数据流 (Global Data Flow)**​|在整个程序中跨函数追踪数据流。|分析跨函数调用的数据传播，用于安全审计等。|更强大，但更耗时、内存消耗大、精度较低。|
|**全局污点跟踪 (Global Taint Tracking)**​|扩展全局数据流，包含非值保留的步骤。|追踪污染在整个程序中的传播路径。|最强大，但资源开销最大。|

#### 2. 关键类与谓词速查表

| 模块/类                             | 关键谓词/成员                                                  | 功能描述                                                                                         |
| -------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **`DataFlow`模块**​                | `localFlow(Node from, Node to)`                          | 判断数据是否能从节点 `from`**本地流动**到节点 `to`（零步或多步）。                                                    |
|                                  | `exprNode(Expr e)`                                       | 获取表达式 `e`对应的数据流节点（`ExprNode`）。                                                               |
| **`DataFlow::Node`**​            | `asExpr()`, `asCfgNode()`                                | 在数据流节点与语法/控制流节点间转换。                                                                          |
| **`DataFlow::LocalSourceNode`**​ | `flowsTo(Node node)`                                     | **（重要）**​ 判断是否存在从**此本地源**到 `node`的本地数据流。一个本地源是数据流图中没有流入边的起点（如参数、新创建值的表达式），使用它可以提升查询性能和结果清晰度。 |
| **`TaintTracking`模块**​           | `localTaint(Node from, Node to)`                         | 判断污点是否能从节点 `from`**本地传播**到节点 `to`。                                                           |
| **全局分析配置**​                      | `module MyConfig implements DataFlow::ConfigSig { ... }` | 定义一个配置模块，必须实现 `isSource`和 `isSink`谓词。                                                        |
|                                  | `module MyFlow = DataFlow::Global<MyConfig>;`            | 应用配置，实例化全局数据流分析模块。                                                                           |
|                                  | `MyFlow::flow(Node source, Node sink)`                   | 使用配置好的模块判断是否存在从源到汇的**全局数据流**。                                                                |
|                                  | `module MyTaint = TaintTracking::Global<MyConfig>;`      | 实例化全局**污点跟踪**分析模块。                                                                           |

#### 3. 工作流程与示例演进

文档通过追踪流向 `os.open(filename)`调用中 `filename`参数的数据，展示了从简单到复杂的查询演进：

1. **仅定位调用**：找到所有 `os.open`调用及其第一个参数表达式。
2. **加入本地数据流**：找到所有能**本地流动**到该参数表达式的节点。
3. **优化为本地源**：将源限制为 `LocalSourceNode`，提升性能与结果可读性。有三种等价写法：
    - 在 `where`子句中添加 `expr instanceof DataFlow::LocalSourceNode`
    - 使用强制转换和 `flowsTo`谓词：`expr.(DataFlow::LocalSourceNode).flowsTo(call.getArg(0))`
    - 使用 `getALocalSource()`谓词：`expr = call.getArg(0).getALocalSource()`
4. **特化源类型**：例如，将源特化为**函数参数**​ (`ParameterNode`)，查找将参数直接用作文件名的情况。
5. **放宽为污点跟踪**：将 `localFlow`改为 `localTaint`，以发现参数**影响**（而不仅仅是值等于）文件名的情况，这通常会发现更多结果。
    

#### 4. 全局数据流/污点跟踪配置模板

这是进行跨函数分析的标准模式：

```
import python
import semmle.python.dataflow.new.DataFlow // 或 TaintTracking

module MyConfig implements DataFlow::ConfigSig {
  // 1. 定义数据从哪里来
  predicate isSource(DataFlow::Node source) {
    source instanceof RemoteFlowSource // 示例：使用预定义的“远程输入源”
    // 或 source = API::moduleImport("os").getMember("getenv").getACall()
  }

  // 2. 定义数据到哪里去
  predicate isSink(DataFlow::Node sink) {
    // 示例：所有文件系统访问操作的路径参数
    sink = any(FileSystemAccess fa).getAPathArgument()
  }

  // 3. （可选）定义屏障，阻止流经特定节点
  // predicate isBarrier(DataFlow::Node barrier) { ... }

  // 4. （可选）定义额外的流步骤
  // predicate isAdditionalFlowStep(DataFlow::Node node1, DataFlow::Node node2) { ... }
}

// 应用配置，实例化分析模块
module MyFlow = DataFlow::Global<MyConfig>; // 或用 TaintTracking::Global

// 使用：查询从源到汇的流
from DataFlow::Node source, DataFlow::Node sink
where MyFlow::flow(source, sink)
select sink, “Data flow from source to sink”, source, source.toString()
```

#### 5. 预定义的实用源与汇

库中提供了许多安全分析中常用的源与汇类，可直接在 `isSource`/`isSink`中使用：

- **RemoteFlowSource**​   (位于`semmle.python.dataflow.new.RemoteFlowSources`)：表示来自网络的远程用户输入。
- **`Concepts`模块**​ 中的类：如 `FileSystemAccess`(文件访问)、`SqlExecution`(SQL执行)、`CodeExecution`(代码执行) 等，这些类本身或其 `getAPathArgument()`等方法常作为汇。
- **`Attributes`模块**​ 中的 `AttrRead`/`AttrWrite`：处理属性访问。
    

#### 6. 创建路径查询 (Path Query)

全局分析可以升级为“路径查询”，以在VS Code中可视化完整的数据流路径。关键步骤：

1. 在查询开头添加特定的元数据（如 `@kind path-problem`）。
2. 导入路径图模块：`import MyFlow::PathGraph`(假设你的流模块是 `MyFlow`)。
3. 从 `PathNode`中选择，并使用 `flowPath`谓词。
4. `select`子句需遵循特定格式，以正确渲染路径。
