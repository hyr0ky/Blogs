
## 域常见架构

![](media/Pasted%20image%2020260204145602.png)  


### 单域、单站点（Smal Office / Lab）
- 

**图内容：**
- 一个 Domain Controller（DC），标注 DC1 (Primary)
- 几台客户端（Workstation）和几台服务器（File/Print/SQL）连到同一交换机/网络段
- 一个简单的 OU 树示意（Users / Computers / Servers）旁注

**说明**
- 适合小型办公室或实验环境。
- 身份验证、组策略、全局目录都集中在单台/少数 DC 上。
- 风险：单点故障（若只有一台 DC）——建议至少部署两台 DC 做复制/冗余。
- 常见端口：LDAP 389 / LDAPS 636 / Kerberos 88 / RPC 135 / SMB 445

### 多 DC + 多站点（Site-to-Site Replication）

**图内容**
- 两个站点（Site A、Site B），每站点各有 DC（DC-A1, DC-A2；DC-B1, DC-B2）
- 各站点内有客户端云与本地服务器；站点间用“复制链路（AD Replication）”连线，注明“站点链接（Site Link）”与复制间隔示意
- 在每个站点下标注 Global Catalog 的位置（GC）

**说明**
- 适用于跨楼层/跨城市组织以降低认证延迟与保证可用性。
- AD 复制基于站点链接（可设置复制频率、成本），站点内通常使用快速同步；站点间可设置低频以节省带宽。
- 注意：DNS 配置、SRV 记录必须正确；站点子网映射要准确，否则客户端可能定位到非预期 DC。
- 常见场景：总部与分支互为故障切换。

### 林（Forest）与子域（Child Domains）结构

**图内容**
- 一个根林（contoso.com），下有两个子域（asia.contoso.com、eu.contoso.com）
- 每个域有自己的 DC 集合、各自的 DNS 域名空间
- 用箭头标注跨域信任（默认为双向信任），旁注“林级别架构/架构主机（Schema Master）与域主机（Domain Master）位置”

**说明**
- 子域常用于：地域隔离、不同法务/合规需求、或复杂委派场景。
- 林中共享 Schema 与配置分区，但每个域有独立的帐号/安全边界（虽有全局目录可跨域查找）。
- 管理复杂度高，通常不推荐仅为便捷管理而创建子域。
- 关键角色（FSMO）分布需规划（Schema Master、Domain Naming Master、RID、PDC、Infrastructure）。


### Hub-and-Spoke（总部 HUB + 分支 RODC）

**图内容**
- 中央 Hub（总部）：多台写入 DC（Writable DC）、可见的 SYSVOL 共享、证书服务（CA）等
- 若干 Spoke（分支）站点：每个分支部署 **只读域控制器（RODC）** 或轻量 DC
- 表示从 Hub 向 Spoke 的单向或双向复制，分支客户端指向本地 RODC 做认证

**说明**
- RODC 适合安全受限或物理不受控的分支（降低凭证泄露风险）。
- RODC 保持只读副本，敏感凭据可以通过凭据缓存策略控制；如果需要写操作则转发到可写 DC（总部）。
- 常见用法：零售、工地、远程办公室。
- 注意 DNS 解析（分支优先本地 DNS）和网络延迟对登录的影响。

### DMZ / 应用隔离（RODC + AD FS / WAP）

**图内容**
- 内网：主林 DCs、证书颁发机构（CA）、域成员服务器
- DMZ（隔离区，一个不同于外网或内网的**特殊网络区域**，DMZ内通常放置一些不含机密信息的公用服务器）：部署 WAP（Web Application Proxy）或 AD FS Proxy，用于发布内部应用（例如 ADFS、远程桌面网关）
- 标注“不要把可写 DC 放在 DMZ”，可在 DMZ 放置 AD LDS 或使用反向代理进行身份桥接

**说明**
- 出于安全，**不要**把可写 DC 放在 DMZ；若必须，建议使用额外隔离、严格的网络/监控与备份策略。
- 常见做法是：内部保留 DC，公开服务通过 WAP/AD FS 代理来进行身份认证中转。
- 若需要 AD 功能在 DMZ（例如某些第三方软件），优先考虑 AD LDS（轻量目录服务）或 RODC，并限制 replicate/credential caching。

## 混合（Hybrid）——On-prem AD + Azure AD（Azure AD Connect）

**图内容**

- 左侧：本地 AD 林（多个 DC、OU）
- 中间：Azure AD Connect 同步服务（可画成一台同步服务器）并注明“密码哈希同步 / Pass-through Auth / ADFS”三种模式
- 右侧：Azure AD（Office 365、Intune、Conditional Access）与用户/设备在云端的示意

**说明**
- 混合身份是现代企业常见模式：部分资源上云（Exchange Online、SharePoint、Teams 等），本地账户通过 Azure AD Connect 同步到 Azure AD。
- 三种常见认证模式：
	- 密码哈希同步（PHS）：同步哈希到 Azure AD（简单、常用）
	- 直通认证（PTA）：Azure 向本地验证请求转发（不在云保存哈希）
	- ADFS：完整联邦认证（更复杂、支持更多自定义策略）
- 安全注意：启用 MFA、Conditional Access、日志与监控，减少 IAM 隐患。
